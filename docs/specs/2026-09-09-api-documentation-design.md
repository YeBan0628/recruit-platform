# 接口文档设计

## 1. 目标

为智能招聘平台当前已经实现的后端接口编写一份可直接用于前后端联调、接口测试和项目展示的 Markdown 文档。

正式文档保存为 `docs/API.md`，以 Gateway 统一入口为主，不引入 SpringDoc、Swagger 等新依赖，也不修改业务代码。

## 2. 文档范围

包含：

- 基础调用说明、鉴权方式、统一响应结构和通用状态码
- auth-service 认证接口
- position-service 职位接口
- resume-service 简历及 AI 匹配接口
- delivery-service 投递接口和状态流转规则
- notification-service 通知接口
- user-service 内部微服务接口

不包含：

- 尚未开发的聊天、附近职位、AI 简历解析和模拟面试接口
- RocketMQ 消息主题的外部调用文档
- 数据库表结构说明
- Swagger/OpenAPI 配置和业务代码改造

## 3. 文档组织

采用单文件、按业务模块分章节的结构：

1. 接口概览
2. 调用约定
3. 认证接口
4. 职位接口
5. 简历接口
6. 投递接口
7. 通知接口
8. 内部微服务接口
9. 状态值与状态流转
10. 联调注意事项

单文件便于当前规模下集中浏览和复制示例；若后续接口数量明显增长，再按服务拆分。

## 4. 调用约定

- 前端统一通过 `http://localhost:8080` 调用 Gateway。
- 登录接口返回的字符串为 Sa-Token，后续受保护接口通过请求头 `token: <登录返回值>` 携带。
- 请求体使用 `application/json; charset=UTF-8`。
- 日期示例使用 `yyyy-MM-dd`，时间响应使用代码实际序列化格式。
- 所有响应均说明 `code`、`message`、`data` 三个字段。
- 文档明确区分公开接口、登录接口和内部微服务接口。

## 5. 单接口内容

每个接口按需包含：

- 功能和 HTTP 方法
- 请求路径及是否需要登录
- 路径参数、查询参数或 JSON 字段表
- 可直接使用的请求示例
- 成功响应示例
- 该接口特有的校验、权限和错误说明

为控制篇幅，共用的分页响应、实体字段和通用错误只集中说明一次，单接口处引用对应约定。

## 6. 业务规则

- 职位状态：`0` 下架、`1` 上架。
- 简历状态：`0` 隐藏、`1` 启用。
- 投递状态：`0` 投递中、`1` 已查看、`2` 面试中、`3` 已录用、`4` 已拒绝、`5` 已撤回。
- 招聘方允许的投递流转为：`0 → 1/2/3/4`、`1 → 2/3/4`、`2 → 3/4`。
- `3`、`4`、`5` 为终态；求职者只能撤回自己的非终态投递。
- 分页参数满足 `page >= 1`、`1 <= size <= 100`；职位热榜满足 `1 <= limit <= 100`。
- user-service 的用户创建和按手机号查询仅供内部 Feign 调用，前端不得直接调用；文档示例不展示密码字段值。

## 7. 安全要求

- 示例统一使用虚构手机号、密码、Token 和业务数据。
- 不记录 MySQL、Redis、Nacos、RocketMQ 密码或 DeepSeek API Key。
- 不把内部用户查询接口描述为前端用户资料接口。
- 以当前 Controller、DTO、校验注解和 Service 权限逻辑为依据，不猜测未实现能力。

## 8. 验收标准

- 文档中的路径、方法、字段、鉴权要求和状态流转与当前代码一致。
- 当前所有 Controller 接口均被覆盖，内部接口单独标注。
- 请求和响应示例可供 Postman、PowerShell 或前端开发直接参考。
- Markdown 层级、表格和代码块可正常阅读。
- `git diff --check` 通过，且不包含业务代码改动。
