# 投递状态机与自动化测试设计

## 1. 目标

约束投递状态只能按业务允许的方向流转，并为现有职位、投递、通知主链路补充自动化测试，减少回归风险。

## 2. 状态定义

| 值 | 含义 | 是否终态 |
| --- | --- | --- |
| 0 | 投递中 | 否 |
| 1 | 已查看 | 否 |
| 2 | 面试中 | 否 |
| 3 | 已录用 | 是 |
| 4 | 已拒绝 | 是 |
| 5 | 已撤回 | 是 |

## 3. 合法流转

- `0 → 1/2/3/4`
- `1 → 2/3/4`
- `2 → 3/4`
- `0/1/2 → 5`（仅求职者撤回）
- 终态不可再次修改或撤回

招聘方接口仍不能设置 `0`、`5`；求职者撤回使用现有撤回接口。

## 4. 测试范围

- position：未登录、非发布者权限、薪资/分页参数校验、缓存失效行为
- delivery：合法/非法状态流转、终态保护、重复投递、幂等锁降级
- notification：事件幂等、状态到通知内容映射、只能查询本人通知

测试使用 JUnit 5 与 Mockito，不依赖外部服务；现有手动接口验证继续保留。

## 5. 兼容性与验收

- 不修改数据库结构和既有接口路径。
- 非法状态流转返回 400，合法流转行为保持不变。
- Maven 全量测试通过。
